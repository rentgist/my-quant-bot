# 알고리즘 검증 기준

수익률이나 승률 하나만으로 전략을 채택하지 않는다. 검증은 비용을 반영하고, 보지 않은 기간에서도 반복되어야 하며, 급락 구간에서의 손실을 함께 측정해야 한다.

## 채택 전 최소 요건

1. **고정된 규칙**: 진입·청산·포지션 크기·거래 불가 조건을 먼저 문서화한다.
2. **분리 검증**: 개발 구간, 고정 홀드아웃, 워크포워드 구간을 분리한다. 홀드아웃 결과를 보고 규칙을 다시 맞추면 새 홀드아웃이 필요하다.
3. **현실 비용**: 수수료, 세금, 호가 스프레드, 슬리피지, 체결 지연을 보수적으로 반영한다.
4. **비교 기준**: 단순 보유와 동일 위험 예산의 기준 전략보다 위험 조정 성과가 나은지 본다.
5. **하방 확인**: 최대 낙폭, 회복 기간, 변동성 급등·급락·유동성 축소 구간의 손실을 별도 보고한다.

## 의사결정 지표

| 범주 | 필수 지표 |
| --- | --- |
| 성과 | 비용 후 수익률, 기대값, 승률, 손익비 |
| 위험 | 최대 낙폭, 변동성, 꼬리손실, 회복 기간 |
| 견고성 | 워크포워드 일관성, 파라미터 민감도, 시장 국면별 성과 |
| 실행성 | 거래 빈도, 유동성, 예상 슬리피지, 데이터 지연 |

## 블랙스완 대응 원칙

- 데이터 신선도·시장 상태·유동성 중 하나라도 불확실하면 신규 진입은 `WAIT`로 낮춘다.
- 사전에 정한 위험 한도(포지션·일일 손실·포트폴리오 낙폭)를 넘으면 확대가 아니라 노출 축소와 재평가를 우선한다.
- 사후 설명을 전략 개선 근거로 쓰기 전에, 같은 규칙이 다음 독립 구간에서도 작동하는지 재검증한다.

이 기준은 연구와 검토용이다. 실거래 전환은 별도의 사용자 승인과 모의·소액 단계 검증이 필요하다.
